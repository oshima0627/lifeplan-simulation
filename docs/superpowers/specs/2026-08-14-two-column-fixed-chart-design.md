# 左フォーム・右グラフ固定の2カラム 設計書

**日付:** 2026-08-14
**対象:** トップページ（`/`）の試算画面
**前の設計:** [2026-08-13-pinned-result-layout-design.md](2026-08-13-pinned-result-layout-design.md)

---

## 1. 何を作るか

1. **広い画面は2カラム。** 左に入力フォーム（縦スクロール）、右にグラフ（固定）。
2. **狭い画面はグラフだけを見せる。** 入力はボタンでポップアップを開いて行う。

利用者の判断（2026-08-14）。

**計算エンジン・保存スキーマ・`worker/` は一切変更しない。** 表示層だけの変更である。

---

## 2. 前の設計から覆すこと

2026-08-13 の設計は「基本情報を横スクロールする1本のバーにして画面上部に固定する」
というものだった。**この形はやめる。**

| 前の設計 | 今回 |
|---|---|
| 全幅で1カラム | 1024px 以上で2カラム |
| 基本情報＝横スクロールのバー（`BasicInfoBar`） | 基本情報＝左カラムで縦積み |
| バーの項目は8つまでという制約 | **消滅する。** 縦積みには項目数の上限が要らない |
| バーとグラフの両方を上部に固定 | **グラフだけを右で固定。** 左は普通に縦スクロール |

**`BasicInfoBar` と `BarField` は削除する。** 縦積みに戻すと役目が無い。
残しても呼ばれないコードになり、次に読む人が「どちらが本物か」を判断できなくなる。

**前の設計から引き継ぐもの（変更しない）:**

- ポップアップを毎回開く
- 押せるステップ表示（`Steps`）・「この内容で見る」・フォーカストラップ
- 判定を1行に圧縮した `VerdictSummary` と、見出し・結末を集約した `verdict.ts`
- グラフの高さ `min(360px, 40vh)`
- 警告に `role="status"` を使う（`role="alert"` も `role="banner"` も使わない）

## 3. 画面の骨組み

### 3.1 広い画面（1024px 以上）

```
┌─ 左カラム（380px・縦スクロール） ─┐ ┌─ 右カラム（残り全幅） ────────────┐
│ 基本情報（7項目・縦積み）          │ │ ┌─ 固定（sticky top-0） ────────┐ │
│  現在の年齢                        │ │ │ 警告行（不正入力のときだけ）   │ │
│  職業                              │ │ │ 判定サマリ（1行）              │ │
│  世帯手取り年収                    │ │ │ 資産グラフ                     │ │
│  年間の基本生活費                  │ │ └────────────────────────────────┘ │
│  現在の貯金                        │ │ 判定の詳細（打ち手・95歳の残高）   │
│  現在の投資額                      │ │ 入力をやり直す / 初期値に戻す      │
│  リタイア予定年齢                  │ │ 保存したプラン                     │
│  年間収支（自動計算）              │ │ 注釈                               │
│                                    │ │                                    │
│ より詳しく（任意）                 │ │ ← ここは固定領域の下でスクロール   │
│  退職金 / 年金 / 子供 / 大きな支出 │ │                                    │
└────────────────────────────────────┘ └────────────────────────────────────┘
```

### 3.2 狭い画面（1024px 未満）

```
┌────────────────────────────────────┐
│ ┌─ 固定（sticky top-0） ─────────┐ │
│ │ 「入力する」ボタン              │ │
│ │ 警告行（不正入力のときだけ）    │ │
│ │ 判定サマリ（1行）               │ │
│ │ 資産グラフ                      │ │
│ └─────────────────────────────────┘ │
│ 判定の詳細 / やり直す / 保存プラン  │
│ 注釈                                │
└────────────────────────────────────┘
```

**左カラムは描画しない**（`hidden lg:flex`）。入力は「入力する」ボタンから
既存のヒアリングポップアップで行う。ポップアップは6ステップで基本情報も任意項目も
すべて持っているので、入力手段は失われない。

### 3.3 なぜ区切りが 768px ではなく 1024px なのか

768px で2カラムにすると、フォーム約340px＋グラフ約340pxになる。
**その幅では資産カーブが横に潰れて読めない。** グラフは「何歳で尽きるか」を
読み取るためのものなので、潰れた時点で存在価値が無い。

既存コードも2カラムの境目に `lg`（1024px）を使っていた。そこに揃える。

### 3.4 固定領域には不透明な背景を敷く

透明のままだと、下からスクロールしてきた文字が固定領域を透かして重なる。
背景は `body` と同じ `bg-slate-50` にする。

## 4. 警告行を右の固定領域に置く

`isRetirementAgeInvalid` / `isPensionStartAgeInvalid` が真のときに出す警告を、
**左カラムではなく右の固定領域に置く。**

**理由:** 狭い画面では左カラムごと入力が消える。警告を左に置くと、
スマホの利用者は「試算が黙って間違っている」ことに一度も気づけない。

前の設計では年金の警告だけを固定領域に出していた（項目は下、警告は上）。
今回はその理由が**すべての警告**に当てはまる。

- **`role="status"` を使う。** 値を変えるたびに読み上げが割り込む `role="alert"` は使わない
- **要素は常に描画し、中身だけを出し入れする。** 要素ごと出し入れすると
  ライブリージョンが中身と同時に挿入され、読み上げが発火しないことがある
- **`role="banner"` は使わない。** これはサイトヘッダのランドマークである
- 該当する入力欄の枠を琥珀色にし、`aria-invalid` を立てる（左カラムが見えているときの手がかり）

---

## 5. 判定カードは今回も全部は固定しない

`DepletionVerdict` は年金0円の警告＋判定＋3枚のカードで縦およそ300px、
グラフが最大360px。合わせて固定すると狭い画面で固定領域が画面を埋める。
**画面高を超えた sticky は下端が永久に見えなくなる。**

固定するのは `VerdictSummary`（1行）まで。打ち手の本文と95歳時点の残高は
固定領域の下でスクロールさせる。

### 6.1 `BasicInfoFields` の中身

**ヒント文を戻す**——前の設計ではバーに収まらないので外していたが、縦積みなら入る。

| # | 項目 | ヒント |
|---|---|---|
| 1 | 現在の年齢 | なし |
| 2 | 職業 | なし |
| 3 | 世帯手取り年収 | 配偶者がいれば合算した額 |

### 6.2 「入力する」ボタン

- 狭い画面にだけ出す（`lg:hidden`）
- 押すと `HearingModal` が開く（`setModalOpen(true)`）
- 固定領域の中に置く。スクロールしても押せる必要がある

**広い画面には出さない。** 左カラムに入力欄が見えているので、ボタンは重複になる。
広い画面から開き直したい人には、下にある「入力をやり直す」がある。

### 6.3 「入力をやり直す」「初期値に戻す」「保存したプラン」の置き場所

**固定領域の下（右カラム側）に置く。全幅共通。**

左カラムに入れると、狭い画面で左カラムごと消えて保存プランに触れなくなる。

## 7. 直さないと嘘になる文言

`DepletionVerdict.tsx` の本文に「**上のバー**を変えてその場で試せます」が2箇所ある
（2026-08-13 に「左のフォーム」から変えたもの）。バーが無くなるので**「左のフォーム」に戻す**。

**これは付随的な修正ではない。** 画面が「打ち手を試す場所」を文章で名指ししており、
名指しの先が消えると、利用者は存在しないものを探すことになる。

⚠️ ただし狭い画面では左のフォームが無い。**「左のフォーム（狭い画面では「入力する」ボタン）を
変えてその場で試せます」**のように、両方の場合を1文に含める。

## 8. テスト

### 8.1 新しく担保すること

1. 基本情報7項目が `BasicInfoFields` に描画される
2. 警告行が `InputWarnings` として描画され、`role="status"` を持ち、常設で中身だけ出し入れされる
3. 「入力する」ボタンを押すとポップアップが開く
4. `BasicInfoBar` / `BarField` への参照がコードベースに残っていない
5. 任意項目（子供・大きな支出）が左カラム側に描画される

### 8.2 書き換えが必要な既存テスト

- `BasicInfoBar.test.tsx` / `BarField.test.tsx` — **削除**
- `Simulator.test.tsx` — 固定領域の中身が変わる。`.sticky` を手がかりにしている
  「任意項目はバーではなくスクロール領域にある」は、新しい構造に合わせて書き直す

### 8.3 テストしないこと

**固定されているか（sticky）と、画面幅による出し分け（`hidden lg:flex` / `lg:hidden`）は
jsdom では検証できない。** jsdom はメディアクエリを評価せず、レイアウトも計算しない。
CSSクラスの有無を見るテストは実装の写経になるだけなので書かない。

**本番デプロイ後に実機で目視する。** 2026-08-13 の設計 §13 で18項目を実測した前例に倣う。

目視する項目:

| 対象 | 期待 |
|---|---|
| 1024px 以上でスクロール | 左が流れ、右のグラフは残る |
| 1024px 未満 | 左カラムが出ない。「入力する」ボタンが出る |
| 「入力する」を押す | ポップアップが開く |
| リタイア年齢を不正にする | 警告行が右の固定領域に出る（狭い画面でも見える） |
| 固定領域の高さ | 画面高を超えない |
| ページ本体の横スクロール | 起きない |
| 判定の本文 | 「左のフォーム」に戻っている |

---

## 9. 意図的にやらないこと

- **計算エンジン・保存スキーマ・`worker/` を触らない**
- **ポップアップの中身を変えない。** ステップ・フォーカストラップ・毎回開く挙動はそのまま
- **`BasicInfoBar` を「スマホ用に残す」ことはしない。** 狭い画面の入力はポップアップに
  一本化する。2つのレイアウトを維持すると、入力項目が2つの部品に分かれたままになる
- **左カラムを `sticky` にしない。** 左は縦スクロールする側である
